## 1. ОРШИЛ

Linux нь өргөн хэрэглэгддэг нээлттэй эхийн үйлдлийн систем бөгөөд түүний гол хэсэг
нь kernel буюу цөм юм. Цөм нь процесс, санах ой, файл, төхөөрөмж болон сүлжээний
нөөцийг удирддаг. Хэрэв бүх боломжийг нэг том програм болгон цөмд урьдчилан оруулбал
цөмийн хэмжээ нэмэгдэж, хэрэггүй хэсэг нь санах ой эзэлнэ. Үүнийг шийдэх нэг арга нь
шаардлагатай боломжийг тусдаа module хэлбэрээр ачаалах явдал юм.

Энэ ажилд Linux kernel module гэж юу болох, модуль хэрхэн ачаалагдаж устдаг, мөн
модульчлагдсан архитектур ямар давуу болон сул талтайг судлав. Мөн жижиг модуль
бичиж, түүнийг Linux-ийн kbuild системээр хөрвүүлэх болон `insmod`, `lsmod`, `dmesg`,
`rmmod` командуудын үүргийг тайлбарлав. Тайлангийн бүтэц, тайлбарын хэв маягийг
М.Золжаргал багшийн тайлан бичих зааварт нийцүүлэн боловсруулсан.

## 2. ЗОРИЛГО

Linux kernel module-ийн үндсэн ойлголт болон модульчлагдсан архитектурын ажиллах
зарчмыг тайлбарлаж, жижиг жишээгээр модулийг үүсгэх, хөрвүүлэх, ачаалах,
шалгах, устгах дарааллыг харуулах.

Зорилтууд:

1. Linux kernel болон kernel module-ийн ялгааг тайлбарлах.
2. Модульчлагдсан архитектурын бүтэц, ажиллах дарааллыг судлах.
3. `module_init()` болон `module_exit()` функцийн үүргийг тайлбарлах.
4. Энгийн kernel module-ийн эх код, Makefile бичих.
5. Модулийн давуу тал, эрсдэл, хязгаарлалтыг дүгнэх.

## 3. ОНОЛЫН СУДАЛГАА

### 3.1 Linux kernel гэж юу вэ?

Kernel буюу цөм нь хэрэглэгчийн програм болон техник хангамжийн хооронд байрладаг
үйлдлийн системийн үндсэн хэсэг юм. Програм шууд диск, сүлжээний карт эсвэл санах
ойтой ажиллахын оронд системийн дуудлагаар дамжин цөмөөс үйлчилгээ авдаг. Цөм нь
CPU-ийн хугацааг процессуудад хуваарилах, виртуал санах ой удирдах, файлд хандах,
төхөөрөмжийн драйвер ажиллуулах зэрэг үүрэгтэй.

Linux-ийн цөмийг ерөнхийд нь monolithic буюу цул цөмийн шинжтэй гэж үздэг. Гэхдээ
энэ нь бүх код заавал цөмийн үндсэн image дотор байна гэсэн үг биш. Linux нь олон
чухал дэд системийг тусдаа ачаалагддаг module хэлбэрээр ашиглах боломжтой. Иймээс
Linux kernel нь цул цөмийн хурд болон модульчлагдсан бүтцийн уян хатан байдлыг
хослуулдаг.

### 3.2 Kernel module-ийн ойлголт

Kernel module гэдэг нь ажиллаж байгаа цөмд системийг дахин ачаалахгүйгээр нэмж,
шаардлагагүй үед буцаан хасаж болох цөмийн код юм [1]. Энгийн хэрэглэгчийн програм
нь user mode-д ажилладаг бол module нь kernel mode-д ажиллах тул цөмийн функц,
төхөөрөмж болон цөмийн өгөгдлийн бүтэцтэй шууд харилцаж чадна.

Module нь ихэвчлэн `.ko` өргөтгөлтэй файл болж үүсдэг. Модульд оролтын функц
(initialization function) болон гарах функц (cleanup function) байдаг. Модуль
ачаалахад оролтын функц нэг удаа ажиллана. Модуль устах үед гарах функц дуудагдаж,
модуль авсан нөөцөө буцаан чөлөөлөх ёстой.

### 3.3 Модульчлагдсан архитектур

Модульчлагдсан архитектур гэдэг нь системийн том боломжуудыг жижиг, харьцангуй
бие даасан хэсгүүдэд хувааж зохион байгуулах арга юм. Linux kernel-ийн хувьд үндсэн
цөм нь процесс, санах ой зэрэг гол үйлчилгээг үзүүлж, төхөөрөмжийн драйвер, файл
систем, сүлжээний нэмэлт боломж зэрэг хэсгүүд module хэлбэрээр орж болно.

Энэ бүтцийн үндсэн хэсгийг дараах байдлаар ойлгож болно.

| Хэсэг | Үүрэг |
|---|---|
| Үндсэн kernel | CPU, санах ой, процесс зэрэг суурь нөөцийг удирдана |
| Module | Нэмэлт боломж эсвэл драйверийг хэрэгжүүлнэ |
| kbuild | Модулийг тохирох kernel-ийн header-тэй хөрвүүлнэ |
| Module loader | Модулийг kernel memory-д байрлуулж ажиллуулна |
| User commands | `insmod`, `modprobe`, `lsmod`, `rmmod` зэрэг удирдлагын хэрэгсэл |

Модуль цөмийн экспортолсон symbol-ийг ашиглаж болно. Хэрэв нэг module нөгөөгийн
функцийг ашиглаж байвал loader нь хамаарлыг шалгана. Иймээс модуль бүрийг тусдаа
ажилладаг жижиг програм гэж ойлгож болох боловч ердийн програм шиг бүрэн тусгаар
санах ойтой биш юм.

### 3.4 Модулийн эхлэх ба дуусах цэг

`module_init()` макро нь модуль ачаалагдах үед ажиллах функцийг бүртгэнэ. Linux-ийн
албан ёсны баримтад энэ макро нь module insertion үед оролтын функц болгон дуудагддаг
гэж тайлбарласан байдаг [2]. Оролтын функц `int` утга буцаана. `0` буцаавал ачаалалт
амжилттай болсон гэж үзэх ба сөрөг error code буцаавал ачаалалт бүтэлгүйтнэ.

`module_exit()` макро нь модулийг устгах үед ажиллах cleanup функцийг бүртгэнэ [2].
Энэ функц нь модуль үүсгэхдээ авсан санах ой, procfs файл, төхөөрөмжийн бүртгэл
зэрэг нөөцийг цэвэрлэх үүрэгтэй. Цэвэрлэхгүй бол kernel memory leak эсвэл дараагийн
ачаалалтад алдаа гарч болно.

### 3.5 Module-ийг хөрвүүлэх арга

Linux kernel module-ийг ердийн хэрэглэгчийн програм шиг `gcc simple_module.c` гэж
хөрвүүлэхгүй. Kernel-ийн өөрийн build систем болох kbuild-ийг ашиглана. Linux-ийн
албан ёсны зааварт external module-ийг `make -C /lib/modules/$(uname -r)/build
M=$PWD` хэлбэрээр хөрвүүлдэг гэж заасан байдаг [3]. Энд `M` нь модулийн эх код
байгаа хавтсыг заана.

Энэ арга нь ажиллаж байгаа kernel-ийн тохирох header, compiler flag болон module
version мэдээллийг ашиглах давуу талтай. Тухайн компьютерийн kernel header байхгүй
бол module хөрвүүлэх боломжгүй. Тиймээс эхлээд `/lib/modules/$(uname -r)/build`
зам байгаа эсэхийг шалгана.

## 4. ХЭРЭГЖҮҮЛЭЛТ

### 4.1 Энгийн модулийн шийдэл

Энэ ажилд `simple_module.c` нэртэй жижиг модуль сонгосон. Модуль ачаалагдахад
`simple_module_init()` функц ажиллаж, kernel log-д мессеж бичнэ. Модуль устахад
`simple_module_exit()` ажиллаж, устсан тухай мессеж бичнэ.

`pr_info()` нь мэдээллийн түвшний мессежийг kernel log buffer-т бичдэг. Энэ гаралт
шууд энгийн терминал дээр харагдахгүй байж болох тул `dmesg` командаар шалгана.
`MODULE_LICENSE("GPL")` нь модулийн лицензийг зааж байна. Лицензийг тодорхой
заахгүй бол kernel зарим боломжийг хязгаарлаж, warning гаргаж болно.

### 4.2 Ажиллуулах дараалал

Модулийн хавтаст дараах командуудыг ажиллуулна.

```bash
make
ls -l simple_module.ko
sudo insmod simple_module.ko
lsmod | grep simple_module
sudo dmesg | tail -n 20
sudo rmmod simple_module
sudo dmesg | tail -n 20
make clean
```

`make` команд нь kbuild ашиглан `.ko` файл үүсгэнэ. `insmod` нь модулийг цөмд
ачаална. `lsmod` нь одоо ачаалагдсан модулиудын жагсаалтаас тухайн модулийг
шалгана. `dmesg`-ээр `module loaded` болон `module unloaded` мессежийг харж болно.
Эцэст нь `rmmod` модулийг цөмөөс буцаан устгана. Эдгээр командуудыг root эрхээр
ажиллуулах шаардлагатай байдаг.

### 4.3 Аюулгүй ажиллагааны анхаарах зүйл

Kernel module нь kernel mode-д ажилладаг учраас энгийн C програмын алдаанаас илүү
ноцтой нөлөөтэй. Null pointer ашиглах, буруу санах ойд хандах, нөөцийг чөлөөлөхгүй
орхих зэрэг алдаа нь системийн тогтворгүй байдалд хүргэж болно. Иймээс туршилтыг
виртуал машин дээр хийх нь зөв. Мөн эхлээд энгийн `printk`/`pr_info` мессежтэй
модуль дээр ажиллаж, дараа нь төхөөрөмж эсвэл санах ойн нарийн үйлдэл нэмэх нь
тохиромжтой.

## 5. ДАВУУ БА СУЛ ТАЛ

### 5.1 Давуу тал

1. Шаардлагатай боломжийг системийг дахин ачаалахгүйгээр нэмж болно.
2. Ашиглахгүй байгаа драйвер, файл системийг санах ойгоос хасаж болно.
3. Төхөөрөмжийн драйвер болон шинэ боломжийг тусдаа хөгжүүлж, турших боломжтой.
4. Үндсэн kernel-ийн кодыг бага хэмжээгээр өөрчлөх замаар нэмэлт боломж оруулна.
5. Нэг module-ийг тохирох kernel-тэй олон системд дахин ашиглаж болно.

### 5.2 Сул тал

1. Module kernel mode-д ажилладаг тул алдаа бүх системд нөлөөлж болзошгүй.
2. Kernel-ийн хувилбар, тохиргоо, symbol өөрчлөгдвөл module ажиллахгүй байж болно.
3. Муу зорилготой эсвэл баталгаагүй module нь системийн аюулгүй байдалд эрсдэлтэй.
4. Module dependency болон нөөцийн цэвэрлэгээг буруу хийвэл устгах үед алдаа гарна.
5. Алдааг хэрэглэгчийн програмын адил энгийн debugger-ээр шалгах нь хэцүү.

## 6. ДҮГНЭЛТ

Энэ ажлаар Linux kernel module нь ажиллаж байгаа цөмд динамикаар нэмэгдэж, буцаан
хасагддаг код болохыг судлав. `module_init()` болон `module_exit()` нь модулийн
амьдралын мөчлөгийн эхлэх, дуусах үйлдлийг тодорхойлдог. Мөн kbuild систем нь
модулийг ажиллаж байгаа kernel-ийн header болон тохиргоотой нийцүүлэн хөрвүүлэхэд
ашиглагддаг.

Модульчлагдсан архитектур нь Linux-д хэрэгтэй боломжийг сонгон ачаалах, системийг
дахин асаалгүйгээр драйвер нэмэх, kernel-ийн хөгжүүлэлтийг хэсэгчлэх давуу талтай.
Гэхдээ module нь kernel mode-д ажилладаг учраас жирийн программаас илүү болгоомжтой
хөгжүүлж, турших шаардлагатай. Энэ тайланд энгийн мессеж хэвлэдэг модулийг жишээ
болгосон бөгөөд цаашид procfs, kernel list болон энгийн төхөөрөмжийн driver-ийг
нэмэн судалж болно.

## ХАВСРАЛТ А. БҮРЭН ЭХ КОД

Бүрэн эх кодыг энэ хавтаст байгаа `simple_module.c` файлаас үзнэ.

```c
#include <linux/init.h>
#include <linux/kernel.h>
#include <linux/module.h>

static int __init simple_module_init(void)
{
    pr_info("simple_module: module loaded\n");
    return 0;
}

static void __exit simple_module_exit(void)
{
    pr_info("simple_module: module unloaded\n");
}

module_init(simple_module_init);
module_exit(simple_module_exit);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("NUM student");
MODULE_DESCRIPTION("A simple Linux kernel module example");
```
