# Үйлдлийн системийн бүтэц — 2-р бүлгийн тэмдэглэл

**Ном:** A. Silberschatz, P. B. Galvin, G. Gagne, *Operating System Concepts*, 10-р хэвлэл  
**Бүлэг:** Chapter 2 — Operating-System Structures

## 1-р нүүр

Үйлдлийн систем нь программ ажиллах орчныг бүрдүүлж, хэрэглэгч ба техник хангамжийг холбодог. Энэ бүлэгт үйлдлийн системийн үйлчилгээ, программтай харилцах интерфейс, дотоод бүтэц, ачаалалт болон алдаа шинжилгээг тайлбарласан.

### 1. Үндсэн үйлчилгээ

Хэрэглэгчид зориулсан үйлчилгээ нь хэрэглэгчийн интерфейс гаргах, программыг санах ойд ачаалж ажиллуулах, оролт/гаралт хийх, файл ба хавтас үүсгэх, унших, бичих, устгах, процессуудыг холбох, алдаа илрүүлэх зэрэг юм. Процессууд мэдээллээ **дундын санах ой** эсвэл **мессеж дамжуулалт** ашиглан солилцоно.

Системийн хэвийн ажиллагаанд CPU, санах ой, диск, төхөөрөмж зэрэг нөөцийг процессуудад хуваарилах, ашиглалтыг бүртгэх шаардлагатай. **Хамгаалалт** нь нөөцөд хандах эрхийг хянадаг бол **аюулгүй байдал** нь хэрэглэгчийг баталгаажуулж, гаднын халдлагаас хамгаална.

### 2. Хэрэглэгчийн интерфейс

- **CLI:** командыг текстээр өгнө. Команд тайлбарлагчийг shell гэдэг. Linux-д bash түгээмэл бөгөөд давтагдах ажлыг shell script-ээр автоматжуулж болно.
- **GUI:** цонх, дүрс, цэс, хулгана ашигладаг тул хэрэглэхэд ойлгомжтой.
- **Touch screen:** утас, таблетыг товших, чирэх зэрэг хөдөлгөөнөөр удирдана.

Интерфейс бол хэрэглэгчийн харах хэсэг бөгөөд үйлдлийн системийн дотоод бүтэц биш. Туршлагатай хэрэглэгчид нарийн болон давтагдах ажилд CLI-г илүү ашигладаг.

### 3. Системийн дуудлага

**System call** нь хэрэглэгчийн программ үйлдлийн системээс үйлчилгээ авах интерфейс юм. Жишээ нь файл хуулахад эх файлыг нээх, шинэ файл үүсгэх, давталтаар уншиж бичих, алдаа шалгах, файлуудыг хаах зэрэг олон system call хийгдэнэ.

Программист system call-ыг ихэвчлэн **API**-аар дамжуулан ашигладаг. Windows API, POSIX API, Java API түгээмэл. Linux/UNIX-ийн C программд `libc` нь API дуудлагыг авч, цөмийн тохирох system call-д шилжүүлнэ. API нь хэрэглэхэд хялбар бөгөөд кодыг зөөвөрлөх боломжийг нэмэгдүүлдэг. Параметрийг цөм рүү регистр, санах ойн блок эсвэл стекээр дамжуулна.

System call-ын зургаан төрөл:

1. **Процессын удирдлага** — процесс үүсгэх, ажиллуулах, хүлээх, дуусгах.
2. **Файлын удирдлага** — файл үүсгэх, нээх, унших, бичих, хаах, устгах.
3. **Төхөөрөмжийн удирдлага** — төхөөрөмж хүсэх, чөлөөлөх, унших, бичих.
4. **Мэдээлэл хөтлөх** — цаг, систем, процессын мэдээлэл авах ба өөрчлөх.
5. **Харилцаа холбоо** — connection, message passing, shared memory ашиглах.
6. **Хамгаалалт** — файл, диск зэрэг нөөцийн зөвшөөрлийг тохируулах.

### 4. Системийн үйлчилгээ, linker ба loader

System utility нь файл удирдах, төлөв харуулах, текст засах, программ хөрвүүлэх, ачаалах, сүлжээгээр холбох зэрэг ажлыг хийнэ. Тасралтгүй ард ажилладаг үйлчилгээг **daemon** гэдэг.

Программ ажиллах дараалал:

`эх код → compiler → object файл → linker → executable → loader → санах ой`

**Linker** нь object файлууд ба санг нэг executable болгоно. **Loader** executable-ийг санах ойд ачаална. Dynamic library-г хэрэгтэй үед ачаалснаар санах ой хэмнэдэг. Linux/UNIX нь ELF, Windows нь PE, macOS нь Mach-O формат ашиглана.

### 5. Программ яагаад үйлдлийн системээс хамаардаг вэ?

Үйлдлийн систем бүрийн system call, executable формат, CPU-ийн заавар ялгаатай тул нэг системд compile хийсэн программ нөгөөд шууд ажиллахгүй. Олон платформд ажиллуулахын тулд Python шиг interpreter, Java шиг virtual machine ашиглах эсвэл стандарт API хэрэглэн платформ бүрд дахин compile хийдэг. **API** нь эх кодын түвшний, **ABI** нь параметр дамжуулалт, stack, өгөгдлийн хэмжээ, binary формат зэрэг доод түвшний интерфейс юм.

## 2-р нүүр

### 6. Дизайн ба хэрэгжүүлэлт

Дизайны өмнө зорилгыг тодорхойлно. Хэрэглэгч системийг хялбар, хурдан, найдвартай, аюулгүй байлгахыг хүсдэг. Хөгжүүлэгч засварлах, өргөтгөхөд хялбар, үр ашигтай байлгахыг зорьдог.

**Mechanism** нь “яаж хийх вэ?”, **policy** нь “юуг хийх вэ?” гэсэн асуултад хариулна. Жишээ нь timer бол CPU-г хамгаалах механизм, харин процесст хэдэн хугацаа өгөх нь бодлого. Эдгээрийг салгавал бодлого өөрчлөгдөхөд үндсэн механизмыг солих шаардлагагүй.

Орчин үеийн үйлдлийн системийг голдуу C/C++ хэлээр, hardware-тай шууд харьцах бага хэсгийг assembly хэлээр бичдэг. Өндөр түвшний хэл нь кодыг ойлгох, засах, өөр төхөөрөмжид зөөхөд хялбар болгоно. Гүйцэтгэлийг зөв алгоритм, өгөгдлийн бүтэц сонгож, bottleneck хэсгийг сайжруулан нэмэгдүүлдэг.

### 7. Үйлдлийн системийн бүтцүүд

- **Monolithic:** цөмийн бүх үйлчилгээ нэг address space-д байна. Маш хурдан боловч томрох тусам засварлах, өргөтгөхөд хэцүү. UNIX, Linux жишээтэй.
- **Layered:** hardware-оос user interface хүртэл давхаргад хуваана. Давхарга бүр доод давхаргын үйлчилгээг ашиглана. Ойлгох, туршихад хялбар боловч олон давхарга дамжих overhead их.
- **Microkernel:** цөмд зөвхөн хамгийн хэрэгтэй удирдлага ба communication үлдээж, бусад service-ийг user space-д ажиллуулна. Өргөтгөх, зөөх, хамгаалахад сайн бөгөөд нэг service унахад бүх систем унахгүй. Харин message passing, process switching-ээс шалтгаалж удааширна. Mach, QNX жишээ болно.
- **Module:** үндсэн цөм дээр driver, file system зэрэг үйлчилгээг boot үед эсвэл ажиллаж байх үед нэмж, хасна. Linux-ийн LKM нь monolithic системийн хурд ба модуль бүтцийн уян хатан байдлыг хослуулдаг.
- **Hybrid:** орчин үеийн системүүд дээрх аргуудыг хослуулна. Linux нь monolithic + module, Windows нь monolithic + microkernel шинжтэй. macOS/iOS-ийн Darwin нь Mach, BSD, I/O kit-ийг нэгтгэдэг. Android нь Linux kernel дээр Bionic, HAL, native library, ART, framework, application гэсэн давхаргатай. HAL нь ялгаатай hardware-ыг программд ижил байдлаар харуулна.

### 8. Үйлдлийн систем бүтээх ба boot хийх

Үйлдлийн системийг source code бэлтгэх, configure хийх, compile хийх, install хийх, boot хийх дарааллаар байгуулна. **Booting** гэдэг нь цөмийг санах ойд ачаалж системийг эхлүүлэх үйл явц:

1. Boot loader цөмийг олно.
2. Цөмийг санах ойд ачаалж эхлүүлнэ.
3. Цөм hardware-ыг initialization хийнэ.
4. Root file system-ийг mount хийнэ.

BIOS нь олон шаттай boot хийдэг бол UEFI нь 64-bit систем, том диск дэмждэг хурдан boot manager юм. Linux-д GRUB цөмийг сонгож ачаална. Түр `initramfs`-аас хэрэгтэй driver, module-ийг ачаасны дараа үндсэн root file system, `systemd` болон бусад service эхэлнэ.

### 9. Алдаа ба гүйцэтгэлийн хяналт

Debugging нь алдаа засахаас гадна удаашралын bottleneck-ийг олохыг хамарна. Process алдаа гарахад log, **core dump**, kernel crash үед **crash dump** хадгалагдаж болно.

**Counter** нь CPU, memory, disk, network-ийн статистикийн утгыг харуулна. Linux-д `ps`, `top`, `vmstat`, `netstat`, `iostat`, `/proc` ашигладаг. **Tracing** нь system call зэрэг тодорхой үйл явдлыг алхам бүрээр нь бүртгэнэ. `strace`, `gdb`, `perf`, `tcpdump` нь жишээ хэрэгслүүд. BCC/eBPF нь ажиллаж буй Linux kernel-д бага нөлөөтэй динамик tracing хийдэг.

### Дүгнэлт

Үйлдлийн систем нь программ ба hardware-ыг холбож, нөөц хуваарилж, хамгаалалт хийж, программ ажиллах орчныг бүрдүүлдэг. Системийн бүтцийг сонгохдоо хурд, найдвартай байдал, аюулгүй байдал, өргөтгөх боломжийг тэнцвэржүүлдэг учраас орчин үеийн системүүд ихэвчлэн hybrid бүтэцтэй байдаг.
