Үйлдлийн систем - Лабораторийн ажил №4
=======================================

Сэдэв: Process State, Process Priority, Context Switching-ийн симуляци

Compile хийх:

```bash
make
```

Ажиллуулах:

```bash
./lab4
```

Цэвэрлэх:

```bash
make clean
```

Тайлбар
-------

Энэ программд 3 процессийг `struct PCB` ашиглан хадгалсан. Процесс бүр `process_id`,
`priority`, `state`, `process_counter`, `burst_time`, `waiting_time` гэсэн мэдээлэлтэй.

Scheduler нь Priority Scheduling ашигласан. Энэ лабораторид priority-ийн тоо бага байх
тусам өндөр эрхтэй гэж үзсэн. Жишээ нь `1` нь `2`-оос, `2` нь `3`-аас өндөр priority.

Process 1 нь random тоонууд үүсгээд эрэмбэлнэ. Process 2 нь 2x2 матриц нэмнэ.
Process 3 нь string доторх үсгийн давтамж тоолно. Process 2 эхний удаа ажилласны дараа
2 алхам WAITING төлөвт орж байгаа.

Тайлангийн асуултын хариулт
---------------------------

1. PCB гэж юу вэ?

PCB буюу Process Control Block нь процессын удирдлагын мэдээллийг хадгалдаг бүтэц юм.
Үүнд процессын дугаар, төлөв, priority, counter гэх мэт мэдээлэл орно.

2. Process state ямар үүрэгтэй вэ?

Process state нь тухайн процесс одоо ямар байдалд байгааг харуулна. Жишээ нь READY,
RUNNING, WAITING, TERMINATED гэх мэт.

3. READY ба RUNNING төлөвийн ялгаа юу вэ?

READY төлөвтэй процесс CPU авахад бэлэн боловч одоогоор ажиллаагүй байна. RUNNING төлөвтэй
процесс яг одоо CPU дээр ажиллаж байна.

4. WAITING төлөв хэзээ үүсдэг вэ?

Процесс I/O эсвэл ямар нэг үйл явдал хүлээх үед WAITING төлөвт орно. Энэ лабораторид
Process 2 матриц нэмсний дараа түр WAITING болж байгаа.

5. Priority scheduling ямар зарчмаар ажилладаг вэ?

Priority scheduling нь READY процессуудаас хамгийн өндөр priority-той процессыг сонгож
CPU дээр ажиллуулдаг. Манай программд бага тоо нь өндөр priority гэсэн дүрэмтэй.

6. Context switching гэж юу вэ?

Context switching гэдэг нь CPU нэг процессоос нөгөө процесс руу шилжих үйлдэл юм. Энэ үед
өмнөх процессын төлөв хадгалагдаж, дараагийн процесс RUNNING болно.

7. Context switching яагаад overhead үүсгэдэг вэ?

Учир нь CPU процессын жинхэнэ ажлыг хийхээс гадна төлөв хадгалах, дараагийн төлөв ачаалах
нэмэлт ажил хийдэг. Энэ нэмэлт хугацааг overhead гэж ойлгож болно.

8. Энэ лабораторийн симуляци бодит үйлдлийн системээс юугаараа ялгаатай вэ?

Энэ программ бодит kernel scheduler биш. Бодит CPU register, interrupt, memory management
хийхгүй. Зөвхөн process state, priority, context switching-ийн санааг энгийн C программаар
дуурайлгасан.
