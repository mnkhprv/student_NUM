# Smart Home вэб интерфейс – Roadmap

Төсөл: Ухаалаг гэрийн автоматжуулалт ба хяналтын систем (ESP32)

## 1. Ерөнхий бүтэц

```
[Сенсорын ESP32] --WiFi/HTTP POST--> [Backend (Node.js + Express)] <--> [Database (SQLite)]
 PIR, LDR, DHT22, HC-SR04                    |   ^
                                             |   | HTTP GET (хөтөч)
[Гүйцэтгэгч ESP32] <--WiFi/HTTP GET--------- |   |
 LED, servo, buzzer, relay                   v   |
                                         [Вэб хуудас (HTML + JS)]
```

- WBS 1.5.2-д "хоёр ESP32" гэж байгаа тул сенсорын ESP32 өгөгдлөө сервер рүү илгээнэ,
  гүйцэтгэгч ESP32 серверээс команд (LED/servo/relay) авна. Ингэвэл ESP32 хоорондоо
  шууд холбогдох шаардлагагүй, хамгийн энгийн.
- Автомат дүрмүүд (харанхуй+хөдөлгөөн → LED, 30°C → buzzer + relay, 5 см → servo)
  **сервер дээр** (`server.js`, `applyRules`) ажиллана. Сенсорын утга ирэх бүрт дүрмийг шалгаад
  төлөв өөрчилнө, гүйцэтгэгч ESP32 зөвхөн төлөвийг татаж pin-үүдийг удирдана.
  Ингэснээр ESP32 код энгийн, дүрмийг нэг газар засна.
- Горим: **автомат** эсвэл **гараар**. Гараар горимд л вэбийн товчнууд ажиллана.
- Гүйцэтгэгч ESP32 `/api/actuators` дээрээс энгийн текст (`led=1`) татна, ингэснээр
  ESP32 дээр JSON library хэрэггүй.

## 2. Database яаж хийх вэ

Сонголт: **SQLite** (нэг файл, суулгах зүйлгүй, багийн хэмжээнд хангалттай).
Дараа нь хэрэв хэрэгтэй бол PostgreSQL рүү шилжүүлж болно (машин дээр `psql` байгаа).

Хүснэгтүүд:

| Хүснэгт | Талбарууд | Зориулалт |
|---|---|---|
| `devices` | id, name, type (sensor/actuator), last_seen | ESP32 бүрийн бүртгэл |
| `sensor_readings` | id, device_id, temperature, humidity, light, motion, distance_cm, created_at | Сенсорын түүх (график зурахад) |
| `device_states` | id, name (led/servo/buzzer/relay), state, updated_at | Одоогийн төлөв (1 мөр = 1 төхөөрөмж) |
| `commands` | id, target (led/servo/relay), value, done (0/1), created_at | Вэбээс өгсөн команд, ESP32 уншаад done=1 болгоно |
| `events` | id, type, message, created_at | "30°C хэтэрлээ", "хаалга нээгдлээ" гэх мэт лог |

Тэмдэглэл:
- Сенсорыг 5 секунд тутам хадгалбал өдөрт ~17 000 мөр болно, SQLite-д асуудалгүй.
- Хуучин өгөгдлийг (жишээ нь 7 хоногоос дээш) хааяа устгана.

## 5. Эрсдэл

- ESP32 болон сервер өөр сүлжээнд байвал холбогдохгүй → нэг WiFi (эсвэл утасны hotspot) ашиглана.
- Компьютерийн IP өөрчлөгдвөл ESP32 алдаа гарна → config-д IP-г нэг газар тавина.
- Relay/servo-д тусдаа тэжээл хэрэгтэй байж болно → USB-ээс татахад ESP32 restart хийж магадгүй.

## 6. Одоогийн байдал

Хийгдсэн:
- Backend, database, бүх API, автомат дүрмүүд, вэб dashboard – компьютер дээр хуурамч өгөгдлөөр
  `curl` болон хөтөчөөр туршиж баталгаажсан.
- ESP32 sketch-үүд бичигдсэн (`esp32/sensor`, `esp32/actuator`).

Хийх үлдсэн:
- ESP32 sketch-үүдийг Arduino IDE-ээр хөрвүүлж, WiFi/IP, pin-үүдийг өөрсдийн холболтоор тохируулан бодитоор туршина.
- LDR-ийн утга (харанхуй үед өндөр эсвэл бага) модулиасаа хамаарна, `readLight()`-ийг шалгах.
- Relay нь LOW-ээр асдаг модуль байж болно, `actuator.ino`-д шалгах.
- Үе 6-ийн нууц үг, MQ хий мэдрэгч – хийгээгүй (сонголт).

## 7. Ажиллуулах

```
cd backend
npm install
npm start
```

Дараа нь хөтөч дээр `http://localhost:3000`. ESP32-ууд компьютерийн IP хаяг руу холбогдоно
(`ip a` эсвэл `hostname -I`-ээр IP-г хараад sketch доторх `SERVER_URL`-д бичнэ).
Компьютер болон ESP32 нэг WiFi-д байх ёстой.

## 8. ESP32 дээр ажиллах хувилбар (нэг ESP32)

Нэг ESP32 байгаа тул `esp32/smarthome/smarthome.ino` бичсэн. Энэ нь сенсор унших, автомат дүрэм,
LED/servo/buzzer/relay удирдах, OLED, болон **вэб серверийг өөрөө** ажиллуулна.
Компьютер, database хэрэггүй. Хөтөчөөр `http://<ESP32-ийн IP>` руу орно.

- Түүх (температур, чийгшил) RAM дотор хадгалагдана (сүүлийн ~15 минут), restart хийхэд арилна.
- Hotspot олдохгүй бол ESP32 өөрөө `SmartHome` нэртэй WiFi үүсгэнэ, хаяг нь `http://192.168.4.1`.
- Өмнөх `backend/` (SQLite-тай) хувилбар нь түүхийг удаан хадгалах сонголт болж үлдэнэ.
- ESP32-ийн IP-г serial monitor (115200) дээр "Хаяг: http://..." гэсэн мөрөөс харна.
- Хөрвүүлж, ESP32 дээр байршуулж, вэб сервер, команд, горим солих зэргийг `curl`-ээр туршсан.
  Сенсорууд pin-үүдэд холбогдсон эсэхийг бодитоор шалгах үлдсэн.
