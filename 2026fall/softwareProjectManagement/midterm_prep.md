## 1. Цаг төлөвлөлт, Gantt, PERT, CPM (үйл ажиллагааны төлөвлөгөө)

**Төлөвлөлтийн 2 хэсэг:** (1) үйл ажиллагааг тодорхойлох, (2) тэдгээрийг цагт нь дуусгах хуваарь гаргах.

**Үйл ажиллагаа төлөвлөх 4 алхам:**
1. Үйл ажиллагааг тодорхойлох (үр дүнгээс ажил, milestone гаргана)
2. Хоорондын хамаарлыг тодорхойлох (дотоод/гадаад, дараалал)
3. Нөөцийг тооцоолох (нөөцийн календарь)
4. Үргэлжлэх хугацааг тооцоолох (ажиллах хүч ба нөөцөөс хамаарна)

| Хэрэгсэл | Юу харуулах вэ |
|---|---|
| **Gantt chart** | Ажил бүр хэзээ эхэлж/дуусах, хэд хоног, хэн хийх, давхцал/хамаарал, төслийн дуусах хугацаа. Хэвтээ тэнхлэг нь хугацаа |
| **PERT diagram** | Ажлуудын сүлжээ. Төслийн хамгийн бага хугацаа, чухал зам. Зурах дараалал: ажил тодорхойлох → дараалал → зурах → хугацаа тооцох → critical path → өөрчлөлтөд шинэчлэх |
| **CPM** | Critical path = төслийн хугацаанд нөлөөлдөг **хамгийн урт зам**. ES, EF, LS, LF, slack тооцно |
| **Precedence network (AON)** | Зангилаа = ажил, сум = хамаарал |

**Томьёо:** (Finish-to-Start, ажлын өдрөөр)
- Forward pass: `ES = өмнөх ажлуудын EF-ийн максимум` (эхний ажил ES = 0), `EF = ES + үргэлжлэх хугацаа`
- Backward pass: `LF = дараагийн ажлуудын LS-ийн минимум` (төгсгөлд LF = төслийн хугацаа), `LS = LF − хугацаа`
- `Slack (float) = LS − ES = LF − EF`. **Slack = 0 бол critical.**
- Critical path дээрх ажил хоцорвол төсөл шууд хоцорно; slack-тай ажил slack-аараа хоцорч болно.

**Хугацаа багасгах арга:** *Crashing* — critical ажилд нөөц нэмнэ (зардал өснө). *Fast tracking* — дарааллаар хийх ажлыг зэрэгцүүлнэ (эрсдэл өснө). Бусад: what-if шинжилгээ, resource leveling, critical chain, risk multiplier.

**Шалгах ёстой:** Gantt нь **хамаарлыг** сайн харуулдаггүй, PERT/сүлжээ нь **хуваарийн календарь**-ыг харуулдаггүй. Дан сүлжээ нь гурван хугацааны үнэлгээгүйгээр бүрэн PERT шинжилгээ биш (Lab6).

## 2. WBS (Lesson 3)

- **WBS** = төслийг дуусгах хүртэл хийх ажлуудын **шаталсан бүтэц** (хийх зүйлс, зөвхөн ажлын жагсаалт биш үр дүнгээр).
- **Хэрэглээ (4):** санаа гаргах хэрэгсэл, архитектур/дизайны хэрэгсэл, төлөвлөлтийн хэрэгсэл, явц тайлагнах хэрэгсэл.
- **Үүсгэх хандлага:** *Top-down* (зорилгоос доош) ба *Bottom-up* (жижиг ажлаас дээш; ажил бичиж → бүлэглэх → давхарыг хасах → шалгах). *Team approach* (бүгдээрээ) ба *Sub-team approach*.
- **Задрах төрөл:** *Noun-type* (бүрэлдэхүүн: физик/функциональ), *Verb-type* (амьдралын цикл: шинжилгээ, загвар, хэрэгжүүлэлт, тест), *Organizational* (хэлтэс, байршил, бизнесийн үйл явц).
- **Сайн WBS-ийн 6 шинж чанар** (хамгийн доод түвшний ажил):
  1. Дуусгах төлөв **хэмжигдэхүйц**
  2. Эхлэх/дуусах үзэгдэл тодорхой
  3. Тодорхой **үр дүн** гарна
  4. Хугацаа, зардлыг хялбар тооцно
  5. Үргэлжлэх хугацаа **хүлээн зөвшөөрөгдөх (≈ 2 долоо хоногоос ихгүй)**
  6. **Бие даасан** (өөр ажлын гаралт хүлээж зогсохгүй)
- **Нэр томьёо:** Activity, Task, Decomposition (задлах), Work Package (хэн, хэзээ, хэрхэн хийх нарийн заавар), WBS dictionary. 1-р түвшин = "chunks of work". Төлөвлөлтийн үед 1–2 удаа л задалдаг.
- Төлөв хэмжих жишээ: "50% дууссан" гэх мэдрэмж **боломжгүй**; "150/300 хуудас гаргаж хүлээлгэж өгсөн" **болно**.

## 3. Хөтөлбөрийн удирдлага, үнэлгээ, нөөц (Lesson 4.1)

- **Programme management** = нэг зорилгод хүрэх хэд хэдэн биеэ даасан төслийг зохицуулах. **5 салбар:** Governance, Project management, Financial management, Infrastructure, Planning.
- **Program planning** ихэвчлэн bottom-up. **Infrastructure** = Administrative (хүний нөөц) + Technical environment and tools.
- **Төсөв (financial):** ажиллах хүч, программ хангамж, ажлын байр, тоног төхөөрөмж, татвар. Бодит зардал ихэвчлэн төлөвлөснөөс их.
- **Төслийн үнэлгээний үндэслэл:** хариуцлага, санхүүжилт зөв зарцуулагдсан эсэх, бодит өөрчлөлт, зорилгод хүрэх эсэх. **Бэрхшээл:** суурь шугам (baseline) байгуулах, тоон ба чанарын үзүүлэлт, оролцогч талуудын санал.
- **Нөөц хуваарилах зарчим:** ур чадвараар хуваарилах, дутагдлыг илүүдлээр нөхөх, what-if, drill-down тайлан, ажил бүрт зардлын анхны утга.
- **Golden thread:** Vision → Blueprint → тооцоолсон ашиг → төслийн багц → бизнесийн шилжилт → хүрэх үр дүн → ашиг хүртэгчид. Санхүүжилтийн 3 арга: өөрийн туршлага, ивээн тэтгэгч, олон нийтийн байгууллага.
- **Техникийн үнэлгээ:** зорилго, хүлээгдэж буй үр дүнг **эхнээс нь** тодорхойлно. *Formative* (явцын) ба *Summative* (нэгдсэн, эхэнд нийт ашиг/хүрээ).

## 4. Үнэ ашгийн шинжилгээ (Cost-benefit, Lesson 4.1–4.2)

- **Cost-benefit analysis** = эерэг (орлого, шууд/шууд бус ашиг) ба сөрөг (зардал, алдагдал) талыг жинлэх арга. Хоёр арга: **cash flow** тооцоо ба **payback** шинжилгээ.
- Системийн үнэ = зардал, системийн ашиг = орлого.
- **Cash flow:** `Зөрүү = Орлого − Зардал`, дараа нь хуримтлагдсан зөрүүг тооцож, 0-ээс давсан үеийг (хугацааг) олно.
- **Payback period** `= Y + A / B`
  - `Y` = нөхөгдөхөөс өмнөх бүтэн жилийн тоо
  - `A` = тэр жилийн эхэнд нөхөгдөөгүй үлдсэн дүн
  - `B` = нөхөгдөх жилийн нийт цэвэр орлого

## 5. Tailoring (PMBOK 8)

- **Tailoring** = менежментийн арга, засаглал, процессыг төслийн орчин ба зорилгод **зориудаар, үндэслэлтэй** тохируулах. Баримт бичиг хийх дургүй учраас орхих нь tailoring **биш**; яагаад хялбаршуулсанаа тайлбарлаж чадвал tailoring.
- **Юуг тохируулах:** development approach (predictive/agile/hybrid), processes, life cycle, deliverables, governance, stakeholder involvement, team involvement.
- **Нөлөөлөх хүчин зүйл:** хэмжээ ба нарийн төвөгтэй байдал, хугацаа/төсөв, эрсдэл, багийн хэмжээ/туршлага, технологи, stakeholder, дүрэм журам, чанарын шаардлага.
- **Логик:** нөхцөл → хэрэгцээ/эрсдэл үнэлэх → арга сонгох → тохируулах → хэрэгжүүлэх → ажиглаж дахин тохируулах. Зөвхөн эхэнд нэг удаа хийдэг ажил **биш**.
- Жишээ (5 оюутан, 10 долоо хоног): charter 1 хуудас, WBS 2–3 түвшин, 5–10 эрсдэл, 7 хоногийн 1 богино update, change control = GitHub issue + багшийн approval.

## 6. Хөдөлмөр ба хугацааны тооцоо (Lesson 5 + Seminar 5)

- **Effort** = хөдөлмөр (хүн цаг/хүн өдөр). **Duration** = эхлэхээс дуустал хуанлийн хугацаа. **Estimate** ≠ амлалт. **Assumption** = үнэн гэж үзсэн, дараа нь шалгах нөхцөл. **Functional size** (FP) ≠ хугацаа.
- Жишээ: 40 хүн цаг, 2 хүн × 4 цаг/өдөр → идеал нөхцөлд 5 өдөр. Хамаарал, хүлээлт байвал уртасна.
- **Тооцоо амжилттай болох нөхцөл:** WBS-ийг сайн хуваах (10–20), ажил бүрийг өмнөх төсөлтэй харьцуулах, таамаглал дэвшүүлэх, **төслийн алхам бүр дээр дахин тооцох**, төлөвлөсөн тооцоог хянах.
- **Буруу тооцох шалтгаан:** өмнөх өгөгдөл дутмаг, туршлага дутмаг, тохирохгүй арга, чухал ажил орхигдсон, бодит бус хүлээлт, тодорхойгүй байдлыг хүлээн зөвшөөрөөгүй.
- **Дуусах огнооны таамгийн график (EQF, Seminar 5-ийн хэлбэрээр):** X = тооцоо хийсэн өдөр, Y = таамагласан дуусах өдөр. Тогтмол бүртгэж, шинэ мэдээлэл ба өөрчлөлтийг харуулна. Энэ нь тоон чанарын коэффициент **биш**.
- **Гурван цэгийн тооцоо:** `E = (O + 4M + P) / 6` (O өөдрөг, M магадлалтай, P гутранги). `SD ≈ (P − O) / 6`. E нь баталгаатай хугацаа биш.
- **Function Point (Albrecht):** 5 төрөл — EI (гаднаас орж өгөгдөл өөрчилнө), EO (тооцоолол бүхий гаралт), EQ (тооцоогүй лавлагаа), ILF (энэ системийн логик өгөгдөл), EIF (өөр системийн, зөвхөн унших). Жин low/average/high.
  - `UFP = Σ (тоо × жин)` (семинарт дунд жин: EI 4, EO 5, EQ 4, ILF 10, EIF 7)
  - `Хөдөлмөр = UFP × бүтээмж (хүн цаг/UFP)`; бүтээмжийн муж (жишээ нь 2–5) өгвөл хөдөлмөрийн муж гарна.
  - Сул тал (лекц): бүрэлдэхүүнийг тодорхойлоход хэцүү, жин "debate and trial"-аар өгөгдсөн, дотоод нарийн төвөгтэй байдлыг тооцдоггүй.
  - **Mark II (Symons):** логик гүйлгээ (оролт, процесс, гаралт) бүрийг тоолно, ISO/IEC 20968.
- Хүн нэмэхэд хугацаа шууд багасахгүй: хамаарал ба харилцааны зардал.

## 7. Хөгжүүлэх аргачлал ба Scrum (Lesson 7)

- **SDLC** = хөгжүүлэлтийн үе шатууд. **Waterfall:** нарийвчилсан төлөвлөгөө эхэнд, явцад өөрчлөх боломжгүй. **Agile:** өөрчлөлтөд уян хатан, богино давталт.
- **Agile тунхаг (2001, 4 үнэт зүйл):** хүмүүс ба харилцаа > процесс/хэрэгсэл; ажилладаг программ > нуршуу бичиг баримт; хэрэглэгчтэй хамтын ажиллагаа > гэрээ; өөрчлөлтөд хариу өгөх > төлөвлөгөө дагах. "Илүүд үзнэ" ≠ "хэрэглэхгүй".
- **Agile аргууд:** DSDM, Kanban, Scrum.
- **Scrum үүрэг:** *Scrum Master* (процессыг хамгаалах, саад арилгах), *Product Owner* (backlog-ийн эрэмбийг хариуцна), *Scrum Team* (5–10 хүн, бие даасан).
- **Уулзалт:** *Sprint planning* (өдрийн хоолны өмнө/дараа 2 хэсэг: 1-р хэсэг Product backlog + sprint goal, оролцогч PO + SM + баг; 2-р хэсэг sprint backlog, SM + баг). *Daily Scrum* **15 минут**, 3 асуулт (юу хийсэн, юу хийх, ямар саад). Шийдэл шийдвэрлэх биш, ирц бүртгэх биш. *Sprint review* (дууссан ажлыг PO-д үзүүлэх, албан бус).
- **Artifacts:** *Product backlog* (эрэмбэлсэн шаардлага, PO хариуцна), *Sprint backlog* (**зөвхөн баг** үүсгэнэ, өдөр бүр шинэчилнэ, ажил 16 цагаас их бол задлах), *Burndown chart* (X = хугацаа, Y = үлдсэн ажил; Sprint/Release/Product 3 төрөл; шулуун биш, заримдаа дээшилнэ).
- **Хэмжээ үнэлэх:** story point, t-shirt size, ажлын өдөр/цаг, WBS, мэргэжилтний туршлага; багийн хурд (velocity) өмнөх туршлагаас.
- **Waterfall vs Agile сонголт:** тодорхойгүй байдал өндөр, шаардлага хурдан өөрчлөгдөх → Agile. Шаардлага бүрэн тодорхой, аудитын баримт шаардлагатай → Waterfall-тай төстэй.
- **Scrum давуу тал:** богино давталтаар туршиж үзнэ, энгийн дүрэм, харилцаа сайн. **Дутагдал:** бичиг баримт бага, хариуцлагын зөрчил.

### 8.3 Гурван цэгийн тооцоо (Seminar 5)

| Ажил | Өмнөх | O | M | P | E = (O+4M+P)/6 |
|---|---|---|---|---|---|
| A | – | 2 | 4 | 6 | 4.00 |
| B | A | 3 | 5 | 9 | 5.33 |
| C | B | 4 | 6 | 10 | 6.33 |
| D | B | 2 | 4 | 8 | 4.33 |
| E | C ба D | 3 | 5 | 9 | 5.33 |

- **Нийт хөдөлмөр** = 4.00 + 5.33 + 6.33 + 4.33 + 5.33 = **25.33 хүн цаг**.
- 3 гишүүн × 2 цаг = 6 цаг/өдөр → доод хязгаар 25.33 / 6 = 4.22 → **5 өдөр** (хамаарал тооцоогүй).
- Нэг ажилд нэг хүн, 2 цаг/өдөр: A→B→C→E = 21.0 цаг → 10.5 өдөр; A→B→D→E = 19.0 цаг → 9.5 өдөр. **Урт зам A→B→C→E → 11 өдөр** (дээш бүхэлчилнэ). Доод хязгаараас (5 өдөр) их болсон шалтгаан: A, B, E дараалалтай, C/D л зэрэг.
- 20% нөөцтэй хөдөлмөр: 25.33 × 1.2 = **30.4 хүн цаг**. Нөөцийг хугацаанд шууд 20% нэмэх нь зөвхөн ажлыг зэрэг хийх боломж, хүн нэмэх нөхцөлд хүчинтэй.

### 8.4 Function Point (Seminar 5)

EI 3 × 4 = 12; EO 1 × 5 = 5; EQ 2 × 4 = 8; ILF 2 × 10 = 20; EIF 1 × 7 = 7.
- **UFP = 52.** Бүтээмж 3 хүн цаг/UFP → **156 хүн цаг**. 2–5 хүн цаг/UFP → **104–260 хүн цаг**.
- WBS-ийн тооцоотой (25.33 цаг) зөрвөл ямар тоог сонгохоос өмнө хүрээ, өгөгдлийн эх үүсвэр, тест ба байршуулалт орсон эсэхийг шалга.

### 8.5 Payback ба cash flow

Хөрөнгө оруулалт 1,000 (мянган ₮). Жилийн цэвэр орлого: 200, 300, 300, 400.
- Хуримтлагдсан: 200 → 500 → 800 → 1200. Нөхөгдөх жил = 4-р жил.
- `Y = 3`, `A = 1000 − 800 = 200`, `B = 400`. **Payback = 3 + 200/400 = 3.5 жил.**
- Лекцийн жишээ: `3 + 50/300 = 3.17 жил`.
- Cash flow жишээ (лекц): орлого 0,0,0,0,100000,100000; зардал 17440, 35700, 35000, 17500, 50000, 5000; зөрүү −17440, −35700, −35000, −17500, +50000, +95000; хуримтлагдсан −17440, −53140, −70700, −52500, +77500, +190000 → **5-р сараас ашигтай**.

## 9. Онолын асуулт, хариулт (өөрөө шалгах)

1. **Gantt chart юу харуулдаг вэ?** Ажил бүрийн эхлэх, дуусах, үргэлжлэх хугацаа, хариуцагч, ажлуудын бүлэглэл/давхцал/хамаарал, төслийн дуусах хугацаа.
2. **PERT хэзээ зурах вэ?** Бодит хуваарь гаргах, critical path олох, зэрэг хийх ажлыг тодорхойлох, хугацаа шахах ажлыг сонгох, чухал биш ажлын хугацааг олох үед.
3. **Critical path гэж юу вэ? Slack гэж юу вэ?** Төслийн хугацаанд нөлөөлөх хамгийн урт зам. Slack = LS − ES; ажил төслийг хоцрууламгүй хэдэн хоногоор хоцрох боломж. Critical ажлын slack = 0.
4. **Crashing ба fast tracking-ийн ялгаа?** Crashing: critical ажилд нөөц нэмж хугацаа богиносгоно (зардал өсөнө). Fast tracking: дараалсан ажлыг зэрэг хийнэ (эрсдэл өсөнө).
5. **ES, EF, LS, LF-ийг яаж олох вэ?** Forward pass-аар ES/EF, backward pass-аар LF/LS. ES = өмнөхүүдийн EF-ийн max; LF = дараагийнхуудын LS-ийн min.
6. **WBS гэж юу вэ? Яагаад хэрэгтэй вэ?** Төслийн ажлын шаталсан бүтэц. Ажлыг төсөөлөх, дизайн, төлөвлөх, явц тайлагнах хэрэгсэл.
7. **Сайн WBS-ийн 6 шинж чанарыг нэрлэ.** Хэмжигдэх төлөв; тодорхой эхлэл/төгсгөл; гарах үр дүн; тооцоход хялбар; ≤ 2 долоо хоног; бие даасан.
8. **Top-down ба bottom-up WBS-ийн ялгаа?** Top-down зорилгоос доош задална; bottom-up жижиг ажлуудыг жагсааж, бүлэглэж, давхарыг хасаж дээш нэгтгэнэ.
9. **Noun-type, verb-type, organizational задралыг тайлбарла.** Бүрэлдэхүүнээр (физик/функциональ), үйл явцаар (амьдралын цикл), байгууллагын бүтцээр.
10. **Work package гэж юу вэ?** Даалгаврыг хэн, хэзээ, хэрхэн хийх нарийн заавар бүхий хамгийн доод түвшний ажлын нэгж.
11. **Programme management ба project management-ийн ялгаа?** Programme нь хэд хэдэн биеэ даасан төслийг (governance, financial, infrastructure, planning-тай) зохицуулна; project нь нэг төслийг төлөвлөж, нөөцийг оновчтой зохицуулна.
12. **Golden thread гэж юу вэ?** Vision-оос эхлээд blueprint, ашиг, шилжилт, үр дүнг холбосон хөтөлбөр зохиох арга (санхүүжилтийн нэг арга).
13. **Cost-benefit analysis ба payback-ийн хоорондын холбоо?** CBA нь зардал/ашгийг жинлэх арга, payback нь хөрөнгө оруулалтаа хэзээ нөхөхийг хэлнэ. Хоёулаа cash flow-д суурилна.
14. **Payback period-ийн томьёо?** Y + A/B.
15. **Tailoring гэж юу вэ, яагаад чухал вэ?** Менежментийн аргыг төсөлд зориудаар тохируулах. Илүүдэл overhead-ийг багасгаж, үнэ цэнийг хамгаална. Баримтыг зүгээр орхих нь tailoring биш.
16. **Tailoring-д нөлөөлөх 3 хүчин зүйл?** Жишээ: төслийн хэмжээ/нарийн төвөгтэй байдал, хугацаа/төсөв, эрсдэл, багийн туршлага, stakeholder-ын тоо.
17. **Effort ба duration-ий ялгаа?** Effort = нийт хөдөлмөр (хүн цаг); duration = хуанлийн хугацаа. 40 хүн цаг, 2 хүн × 4 цаг → 5 өдөр (идеал).
18. **Яагаад тооцоолол буруу гардаг вэ?** Өмнөх өгөгдөл/туршлага дутмаг, тохиромжгүй арга, чухал ажил орхигдсон, бодит бус хүлээлт, тодорхойгүй байдлыг тооцоогүй.
19. **Function Point-ийн 5 төрлийг ялга.** EI, EO, EQ, ILF, EIF (дээрх тайлбар). EQ нь EO-оос "тооцоолол/үүсмэл өгөгдөлгүй" гэдгээрээ ялгаатай.
20. **FP нь хөдөлмөр мөн үү?** Үгүй. Функцийн хэмжээ. Хөдөлмөр = UFP × бүтээмж; бүтээмжийг өмнөх төслөөс авна.
21. **Дуусах огнооны таамгийн график юу харуулдаг вэ?** Таамгийн өөрчлөлтийн тренд. Шинэ мэдээлэл (шалтгаан)-тай холбож төслийн тодорхойгүй байдлыг ойлгоход тусална. Хойшилсон нь дангаараа бүтээмж муудсаны нотолгоо биш.
22. **Agile тунхгийн 4 үнэт зүйл?** Дээрх §7.
23. **"Ажилладаг программ" гэдэг нь бичиг баримтгүй гэсэн үг үү?** Үгүй. Зөвхөн хэрэгтэй бичиг баримтыг хийнэ, нэмэлт баримтаас ажилладаг программыг илүүд үзнэ.
24. **Scrum-ийн 3 үүрэг ба тэдний хариуцлага.** SM: процесс, саад арилгах. PO: backlog-ийн эрэмбэ, юуг хийх. Team: sprint backlog үүсгэж хэрэгжүүлэх.
25. **Daily Scrum хэдэн минут вэ? Юу нь биш вэ?** 15 минут. Асуудал шийдэх, ирц бүртгэх уулзалт биш.
26. **Product backlog ба sprint backlog-ийг хэн хариуцдаг вэ?** Product backlog: Product Owner. Sprint backlog: зөвхөн баг.
27. **Burndown chart-ын шугам яагаад дээшилдэг вэ?** Шинэ ажил нэмэгдсэн эсвэл тооцоо өөрчлөгдсөн бол үлдсэн ажил өснө.
28. **Waterfall ба Agile-ыг хэзээ сонгох вэ?** Шаардлага тодорхой, зохицуулалттай → Waterfall-тай төстэй. Тодорхойгүй, өөрчлөлт хурдан → Agile.

## 10. Алдах эрсдэлтэй цэгүүд

- CPM-д **max / min**-ийг андуурах: forward pass-д max, backward pass-д min.
- Slack = 0 бол critical, гэхдээ **бүх** slack = 0 зам critical path-ийн нэг хэсэг гэж үзнэ.
- WBS-ийн хамгийн доод түвшний ажил **үр дүнтэй** байх ёстой. "Backend хийх" шиг өргөн нэр буруу.
- Payback-д `A` нь тэр жилийн **эхэнд** үлдсэн дүн, `B` нь тэр жилийн **нийт** орлого.
- FP-г хоногоор шууд хөрвүүлж болохгүй. Бүтээмжийг өгөгдсөн гэж үз.
- Хугацаа тооцоход хамаарал, зэрэгцээ ажлыг тооцохгүй бол дан нийлбэр/хүчин чадал хэт богино гарна.
